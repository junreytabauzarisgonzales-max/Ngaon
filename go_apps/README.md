# Ngaon apps: Ngaon · Ngaon Rider · Ngaon Merchant

Flutter (GetX) monorepo for **Ngaon**, a delivery super-app for Bongao, Tawi-Tawi. It combines Ride, Food, Pabili and Padala on one shared rider fleet.

| App | Folder | Android applicationId |
| --- | --- | --- |
| Ngaon (customer) | `apps/customer` | `com.goapp.customer` |
| Ngaon Rider | `apps/rider` | `com.goapp.rider` |
| Ngaon Merchant | `apps/merchant` | `com.goapp.merchant` |

> Package IDs keep the original `com.goapp.*` names. Changing them makes Android treat the apps as new installs and needs new Firebase app registrations. Internal code names (`go_core`, `GoColors`…) are unchanged.

Shared code lives in `packages/go_core`: config, theme, translations (en/fil), network (Dio + WebSocket), services, all models, repository interfaces, HTTP and mock implementations, and shared widgets.

The backend (Golang) is not built yet. **[`API_CONTRACT.md`](API_CONTRACT.md) is the contract it must implement.** Until then every app runs fully in **mock mode**.

## Requirements

* Flutter 3.47+ / Dart 3.13+ (pub workspaces)
* Android SDK **platform 37** installed (compile SDK 37, required by flutter_local_notifications 23; min SDK 23); JDK 17–21 for Gradle
* `dart pub global activate melos` (Melos 8; its config lives in the root `pubspec.yaml` under `melos:`, which replaces `melos.yaml` since Melos 7)

## Quick start (mock mode, no backend needed)

```bash
melos bootstrap                 # or: flutter pub get (from the repo root)
cd apps/customer && flutter run --dart-define=USE_MOCK_API=true
cd apps/rider    && flutter run --dart-define=USE_MOCK_API=true
cd apps/merchant && flutter run --dart-define=USE_MOCK_API=true
```

`USE_MOCK_API` defaults to `true`, so a plain `flutter run` also works.

### Mock mode cheat sheet

| What | How |
| --- | --- |
| OTP code | always `123456` |
| New user (customer asks for a name; rider gets the signup + documents flow) | any number ending in `1111`, e.g. `9171231111` |
| Merchant "not registered" screen | any number ending in `0000` (merchant app) |
| Customer | A new job walks through every status every few seconds, with the rider marker moving. Food waits ~5 s for the simulated merchant. Pabili stops at *items purchased* until you confirm the receipt. GCash/Maya auto-confirm after ~6 s. |
| Rider | Go online → an offer arrives after ~5 s, then every ~30 s. Offers cycle ride → food → pabili → padala. Food becomes ready ~12 s after accept. Pabili auto-confirms 5 s after the receipt. Top-ups are credited after ~6 s. A new rider is approved ~8 s after submitting documents. |
| Merchant | While open, `order.new` arrives after ~8 s, then every ~45 s (looping alarm). After accept, a rider is assigned after ~8 s. After *Mark ready*, the rider picks up after ~6 s. Unaccepted orders auto-cancel at the 3-minute deadline. |

Seed data (5 Bongao merchants with menus and add-ons, saved places, past jobs, wallet history, sales, payouts) is in `packages/go_core/assets/mock/*.json`. It's generated by `python packages/go_core/tool/gen_fixtures.py`. These files are also the contract examples for the backend.

## Backend (Golang)

`backend/` is a Go server that implements [`API_CONTRACT.md`](API_CONTRACT.md) (REST + WebSocket). It uses **PostgreSQL** for persistent relational storage with automated migrations (`migrations/000001_init_schema.up.sql`) and **Redis** (`internal/repository/redis`) for caching, hashed OTP/session management, JWT revocation blacklisting, distributed rate limiting, geospatial rider indexing, and WebSocket Pub/Sub fan-out. A fallback file store (`/data/state.json`) is also supported when `DATABASE_URL` is unset. See [`backend/README.md`](backend/README.md) for the full architecture, security design, and complete endpoint documentation.

```bash
cd backend
cp .env.example .env          # set PUBLIC_URL and review PostgreSQL / Redis credentials
docker compose up -d --build  # Starts PostgreSQL (go-postgres:5433), Redis (go-redis:6379), and Go API (go-api:8080)
docker logs -f go-api         # request log, OTP codes, dispatch decisions
go test ./...                 # end-to-end, security, and integration tests
```

Build the apps against it:

```bash
flutter build apk --release --dart-define=USE_MOCK_API=false \
  --dart-define=API_BASE_URL=http://192.168.x.x:8080 --dart-define=WS_URL=ws://192.168.x.x:8080
```

Dev stand-ins until real providers are connected:

| Feature | Dev behaviour |
| --- | --- |
| SMS OTP | Code is printed in `docker logs go-api`; `DEV_OTP_CODE` (default `123456`) also works |
| GCash / Maya | `checkout_url` opens a backend page with **Pay** / **Simulate failed payment** |
| Photo uploads | Signed `PUT` URLs served by the backend; files under `/data/uploads`, served at `/files/...` |
| Masked calls | `/call` returns the other party's real number (no telephony proxy yet) |
| Push (FCM) | Device tokens are stored, nothing is sent yet; live updates use the WebSocket |
| Rider approval | Auto-approves after `AUTO_APPROVE_RIDERS_SECONDS`; or approve/reject at `/admin?token=ADMIN_TOKEN` |
| Rider wallet | New riders get `RIDER_START_BALANCE` so they can go online; top-ups use the dev payment page |
| Location | `DEV_ANY_LOCATION=true` accepts any pickup/drop-off; `MAX_DISPATCH_M=0` offers jobs to riders at any distance |

Seeded merchant owner numbers for Ngaon Merchant: `9193334444` (Kusina Bongao), `9193334445` (Pantay Grill), `9193334446` (Sitti Bakeshop), `9193334447` (Tiula Halo-Halo), `9193334448` (Bud Bongao Coffee). Any other number gets "not registered as a merchant".

Live contract test (real HTTP + WebSocket repositories against a running server):
`GO_API=http://127.0.0.1:8080 flutter test packages/go_core/test/live/live_api_test.dart`

> The Android manifests allow cleartext `http://` for this local setup (`usesCleartextTraffic`). Use HTTPS and remove that flag before any release.

## Environments and provider keys

### Apps: `env/*.json` + `--dart-define-from-file`

| File | Committed | Use |
| --- | --- | --- |
| `env/mock.json` | yes | Mock mode, no backend |
| `env/example.json` | yes | Template for real environments |
| `env/local.json` | no (git-ignored) | Your LAN backend; add `GOOGLE_MAPS_KEY` here |

```bash
cd apps/customer
flutter run --dart-define-from-file=../../env/local.json
flutter build apk --release --dart-define-from-file=../../env/local.json
```

`GOOGLE_MAPS_KEY` is the **Android Maps SDK key** (restrict it to the three package names and your SHA-1). Gradle injects it into the manifest. Without it the apps draw a simple schematic map (routes included).

### Backend: `backend/.env`

| Key(s) | Provider | Enables | Without it |
| --- | --- | --- | --- |
| `GOOGLE_MAPS_API_KEY`, `GOOGLE_ROUTES_TRAVEL_MODE` | Google Maps Platform (enable Routes API, Geocoding API, Places API (New); server key) | Road distance/ETA for prices, route line on maps (`route_polyline`), real reverse geocoding and place search | Straight-line distance ×1.3, built-in Bongao landmarks |
| `DIDIT_API_KEY`, `DIDIT_WORKFLOW_ID`, `DIDIT_WEBHOOK_SECRET` | Didit | Rider identity verification (ID + selfie liveness). Riders are approved when Didit approves. | No KYC step; `AUTO_APPROVE_RIDERS_SECONDS` or `/admin` |
| `PAYMONGO_SECRET_KEY`, `PAYMONGO_WEBHOOK_SECRET` | PayMongo | Real GCash / Maya hosted checkout for bookings and rider top-ups; automatic refunds when a paid booking is cancelled | Dev payment page with Pay / Fail buttons |

Apply changes with `docker compose up -d` (from `backend/`). The startup log line `integrations: google_maps=… didit_kyc=… paymongo=…` shows what is on.

**Webhooks** need a public HTTPS URL (both providers reject plain IPs). Point `PUBLIC_URL` at a tunnel or domain and register:
- PayMongo: `${PUBLIC_URL}/webhooks/paymongo`, event `checkout_session.payment.paid`
- Didit: `${PUBLIC_URL}/webhooks/didit`, event `status.updated`

Until then the backend **polls** PayMongo and Didit whenever the app is waiting on a payment or a verification, so both work on a LAN. Webhooks never mark anything paid or approved by themselves: the backend re-fetches the payment or decision from the provider's API first.

Google's terms require a notice wherever two-wheeler routes are shown; the apps show "Motorcycle routes are in beta…" under route maps.

## `--dart-define` values

| Key | Default | Meaning |
| --- | --- | --- |
| `USE_MOCK_API` | `true` | `false` = use the real HTTP and WebSocket implementations |
| `API_BASE_URL` | `http://10.0.2.2:8080` | Backend root (the app appends `/api/v1`). `10.0.2.2` is the host machine from the Android emulator. |
| `WS_URL` | `ws://10.0.2.2:8080` | WebSocket root (the app appends `/ws?token=…`) |
| `GOOGLE_MAPS_KEY` | *(empty)* | Google Maps Android key. Injected into the manifest by Gradle. Without it the apps show a lightweight schematic map instead of Google Maps. |

Against a real backend:

```bash
flutter run \
  --dart-define=USE_MOCK_API=false \
  --dart-define=API_BASE_URL=https://api.go.example \
  --dart-define=WS_URL=wss://api.go.example \
  --dart-define=GOOGLE_MAPS_KEY=AIza...
```

Release APK: `flutter build apk --release --dart-define=...` (R8 minify and resource shrinking are enabled). Replace the debug signing config in `android/app/build.gradle.kts` before shipping.

## Firebase (push) setup: one project, three Android apps

1. Create one Firebase project, e.g. `go-bongao`.
2. Add **three Android apps** to it, with package names `com.goapp.customer`, `com.goapp.rider` and `com.goapp.merchant`.
3. Download each app's `google-services.json` into
   `apps/customer/android/app/`, `apps/rider/android/app/` and `apps/merchant/android/app/` respectively. (The files are git-ignored.)
4. Rebuild. Gradle applies the `com.google.gms.google-services` plugin **only when the file exists**. Without it the apps build and run with push disabled; WebSocket keeps working.

The backend sends **data-only, high-priority** messages with `type` + IDs (`job_id`, `offer_id`, `order_id`). In the background, the rider and merchant apps show a full-screen alarm notification for `offer.new` / `order.new`. After login each app registers its token with `POST /me/devices`.

## Architecture

```
packages/go_core/lib/
  bootstrap.dart              initGoCore(), buildGoApp(), bootstrapGoApp(), AuthMiddleware, GoRepositoryBinding
  config/app_config.dart      app type + --dart-define values
  network/                    ApiClient (Dio: headers, single-flight token refresh, GET retry, redacted debug log),
                              ApiException, RealWsClient (heartbeat, backoff + jitter, 4001 refresh), typed WsEvents
  services/                   AuthService, StorageService (get_storage drafts), SessionStore (secure storage),
                              UploadService (compress → presign → PUT), LocationService (foreground service),
                              NotificationService (alarm sound + vibration, wakelock), PushService, NetworkStatus
  models/                     every model in API_CONTRACT §3 (json_serializable)
  repositories/               interfaces, http/, mock/ (MockBackend simulator + Mock*Repository + MockWsClient)
  utils/                      money, validators (PH phone), Manila time, job_flow (status ↔ UI), error handler
  widgets/                    login flow, location picker, job timeline, rider card, chat, photo upload tile,
                              floating "pop-out" nav bar, money text, empty/error/offline states, dialogs
apps/<app>/lib/
  main.dart                   AppConfig(app: …) + bootstrapGoApp()
  app/routes, app/bindings, app/services, app/translations
  modules/<feature>/          view.dart + controller.dart + binding.dart
```

Rules the code follows:

* Controllers call **repository interfaces only**. Bindings pick HTTP or mock from `USE_MOCK_API`.
* Buttons come from `allowed_actions` plus the status. No business rules are hard-coded (see API_CONTRACT §4).
* Money is integer centavos everywhere (`formatCentavos` → `₱1,234.50`). Times are shown in Asia/Manila.
* Drafts survive app kills: cart, Pabili list, Padala form, rider signup, menu item edits in progress.
* Other parties' phone numbers are never shown. Calls go through `/jobs/{id}/call`.

### UI

* Floating, pill-shaped bottom navigation that "pops out" from the screen. The selected tab lifts, scales up and shows its label (`GoFloatingNavBar` / `GoNavShell`).
* New screens open with a short pop-out (scale + fade) transition, `PopOutTransition`.
* Both are short, transform-only animations, so they stay cheap on low-end Android phones.
* The merchant order board shows four columns at ≥ 720 dp (tablet on the counter) and tabs on phones.
